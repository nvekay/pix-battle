Сделать билд этапа 1 играбельным по картинке: игрок с первого взгляда видит свою страну, соседей по имени, где идёт фронт, где холмы и горы, и читает панели без расшифровки сырых чисел.

Конкретные проблемы текущего билда (скриншот `ui-fronts-formations.png`) и их фикс — бриф 06, раздел «Что мешает играть».

## 3. Жёсткие правила этого куска

- Суша, полосы рельефа (`Terrain`) и столицы для любого сида **не меняются**. `MapGen` не делает ни одного нового вызова потока `MapGen`.
- Запекание, декор, шум цвета, камера живут в `Game` и на мир не влияют. Случайность рендера — хеш индекса клетки, **не** `RngStreams` (ядро о ней не знает).
- Рендер по-прежнему только читает мир между тиками. Одна текстура владельцев 512×256 + палитра в шейдере. GameObject на клетку, на дерево или на значок нет: значки и подписи — элементы UI Toolkit.
- `palette.json` читает только рендер, он **не входит в `dataHash`** (смена цвета не должна ломать реплеи). `nations.json` входит, как раньше: его смена ломает старые реплеи кодом 2, это ожидаемо.
- Числа баланса не трогаем.

## 5. Правила и формулы

### 5.1. `Elevation` и `Biome` в генерации (ядро)

- `Elevation[i] = bin[i] * 255 / (Bins − 1)`, деление к нулю, для всех пикселей. `bin` уже посчитан на шаге 3 (`Bins = 1024`), новых вызовов потока нет. Пороги полос (`Relief`) считаются по тем же `bin`, поэтому `Terrain` и `Elevation` согласованы: у каждого холма `Elevation` не меньше, чем у любой равнины, у каждой горы — не меньше, чем у любого холма (с точностью до деления корзины на 4; тест 12.1 проверяет по корзинам).
- **Влажность:** шум `fbm` по октавам `moistureCells` из потока `RngStream.Biome`, той же функцией шума, что высота (целые), нормированный к 0..10 000. **Температура:** `temp_bp = y * 10 000 / (H − 1) − hl_bp / 2`, где `hl_bp` — высота суши над уровнем моря 0..10 000 (север сверху, y = 0 — север, как в `gen_part.py`).
- **Биом** (порядок важен, последнее правило выигрывает): вода → `None`; суша → `Grass`; влажность > `forestMoist` → `Forest`; < `steppeMoist` → `Steppe`; < `desertMoist` и `temp` > `desertTemp` → `Desert`; `temp` < `tundraTemp` → `Tundra`; `Terrain = Hills` → `Hills`, но при влажности > `hillsForestMoist` → `Forest`; `Terrain = Mountains` → `Mountain`, верхние `snowShareOfMountains` гор по `Elevation` → `Snow`; равнина не дальше `beachMaxDist` от воды и `temp` > `tundraTemp` → `Beach`.
- `Biome` на фронт не влияет (решение этапа 3).

### 5.2. Хеш

`HashJob` и `HashManaged`: после `Terrain` идут `Elevation`, затем `Biome`, на каждой контрольной точке, как `Terrain`. Формат реплея не меняется (команды те же); `dataHash` меняется из-за `rules.json` и `nations.json`.

### 5.3. Запекание (`Game/TerrainBaker`, один раз при старте партии)

Размер: `S = cellPx = 6`, `PAD = max(terraceOffsets) = 44`, текстура `W·S × (H·S + PAD)` = 3072 × 1580. Север сверху.

**Уровень клетки.** `L(water) = 0`. Для суши уровень берётся из диапазона полосы `bandLevels`: `[a, b]` для полосы клетки, `eMin`, `eMax` — минимум и максимум `Elevation` по клеткам этой полосы на карте (считает баке́р),
`L = a + (Elevation − eMin) · (b − a + 1) / (eMax − eMin + 1)`, целые, к нулю. Отсюда гарантия: равнина всегда уровень 1, холмы 2–3, горы 4–6, то есть **каждый обрыв между полосами — это граница игрового рельефа**. `off = terraceOffsets[L]`.

**Проход 1, земля (`IJobParallelFor` по 512 столбцам клеток, Burst, `CompileSynchronously`).** Каждый столбец пишет только в свои `S` столбцов текстуры, поэтому записи не пересекаются. Внутри столбца ряды с севера на юг, для клетки `(x, y)`:
- *Верх:* строки `by ∈ [y·S + PAD − off, y·S + PAD − off + S − 1]`. Цвет `biomeTop` × (1 ± шум `topNoise` по хешу пикселя) × (1 + `levelLight`·L). Нижняя строка верха светлее на `rimLight`, если клетка южнее ниже. Верхние min(off(север) − off, 4) строк темнее на `aoDark`, если северный сосед выше. Вода: тон `water.tones` по расстоянию до суши (Чебышёв, `toneDist`), пена на расстоянии 1 у каждого третьего пикселя по хешу, на 3 строки ниже суши темнее на 22% (тень обрыва).
- *Стена:* строки от конца верха до начала верха южной клетки: `[y·S + PAD − off + S, (y+1)·S + PAD − off(юг) − 1]`, высота `off − off(юг)`, если она > 0. У последнего ряда карты — до `H·S + PAD − 1`. Цвет `biomeWall`, к низу темнее до `wallDarkToBottom`, каждая `strataEvery`-я строка темнее на `strataDark`.
- *Запись:* `TerrainColor[px]` (RGBA32, в альфе вид пикселя: 0 вода, 1 верх, 2 стена, 3 декор) и `CellId[px] = (x, y)`. Южная клетка пишется позже и перекрывает северную, это и есть правильный порядок вида «сверху-спереди». Пиксели над картой: `CellId = (0xFFFF, 0xFFFF)`, цвет `sky`.

**Проход 2, декор (`IJob`, Burst, один поток).** Для каждой клетки суши `r = hash(x, y, seed) % 10 000`; если `r < decorDensity[Biome]`, ставится спрайт по правилам `mock25.py` (лес: ели при `temp < 32%`, иначе три вида лиственных по `r % 3`; луг: дерево или куст; тундра: ели; снег: ель в снегу; пустыня: кактус или камень; холмы: камень или малое дерево; горы: камень; степь: куст), якорь в точке `(x·S + S/2 + jx, y·S + PAD − off + S − 1)`, `jx = (r / 7) % 3 − 1`. Спрайты идут по рядам с севера на юг, внутри ряда по x. Пиксель спрайта пишется, только если `CellId[px].y ≤ y` (земля под ним не южнее самого дерева; так южная терраса закрывает ствол северного дерева). `CellId` у пикселя спрайта **не меняется** (остаётся клетка земли под ним), альфа = 3. Тень: 2 строки (3 у высоких) под спрайтом со сдвигом на 1 px вправо, только по пикселям вида 1, ×0,72.

`seed` декора — младшие 32 бита сида партии; хеш — тот же FNV, что в `mock25.py` (`x·73856093 ^ y·19349663`), формулу записать в коде комментарием.

**Мипы.** `TerrainColor` с мипом 1 (усреднение 2×2) для зума ½. `CellId` (`TextureFormat.RG32`, 16 бит на канал) без мипов. В brief-02 было RG16: при 131 072 клетках 16 бит не хватает, поэтому две 16-битные координаты.

**CPU-копия `CellId`** (`ushort[]` ×2, ~19 МБ) остаётся у `MapView` для пикинга мышью.

### 5.4. Шейдер `MapBaked` (каждый кадр, один квад)

Входы: `_TerrainColor`, `_CellId`, `_OwnerTex` (R8 512×256, как сейчас), `_PaletteTex`, `_FrontFxTex` (как сейчас), `_PairStatus` (R8 16×16: 0 мир, 1 война, 2 перемирие; в этом куске `Game` пишет 1 для всех пар живых наций, контакт = война), `_HumanId`, `_FocusNation`, `_Zoom` (½, 1, 2), ручки из `palette.json`.

Для экранного пикселя:
1. `c = CellId(uv)`. Нет клетки → `sky`. `kind` — альфа мипа 0, цвет — мип 0 или 1 по зуму (точечная выборка).
2. `owner = Owner(c)`. Вода или `owner = 0` → цвет без тонировки.
3. **Тонировка «Цвет»:** `t = nationColor · luma(base) / luma(nationColor)` (с ограничением 1), `col = lerp(base, t, s)`, `s = tint[зум][свой ? 1 : 0] × tintKindMult[kind]`.
4. **FrontFx** по клетке `c`, как сейчас (взятая светлее, потерянная темнее, остывает за `fx.seconds`).
5. **Граница в экранном пространстве.** Для `d = 1..(linePx + fringePx[зум])` смотрим 4 экранных соседа на расстоянии `d` (через `ddx/ddy` от uv), берём их клетки и владельцев. Если у соседа суша с владельцем `o ≠ owner` (и хотя бы один из двух не 0): `d ≤ linePx` → линия, иначе → кайма. Стиль по `_PairStatus[owner, o]`:
   - *война:* линия `border.line`, кайма своего цвета: у человека `ownFringe` (белая), у остальных `nationColor` светлее на `otherFringeLight`;
   - *мир:* линия `peaceLine` с прозрачностью `peaceAlpha`, каймы нет;
   - *перемирие:* линия как у войны, штрих `truceDash` px вкл / выкл по экранной координате вдоль границы, каймы нет;
   - граница с ничьей землёй: линия цветом нации, кайма только у нации.
   Граница рисуется после тонировки и декора, то есть **поверх деревьев**. Каждая сторона рисует свой пиксель линии, итого линия 2 px на любом зуме.
6. **Фокус:** у пары (человек, `_FocusNation`) кайма белеет с пульсом 2 Гц.

Значков в шейдере больше нет: столицы, штабы, крепостей нет вовсе — всё в UI (раздел 10). `_StrikeMask` удаляется.

### 5.5. Камера (`Game/MapCamera`)

`PixelPerfectCamera` убирается. Ортографическая камера, 1 юнит мира = 1 пиксель запечённой текстуры.
- `k = max(1, Screen.height / 1080)` (целое). Зумы `z ∈ {k/2, k, 2k}` экранных пикселей на пиксель текстуры, по умолчанию `k` («1:1»). `orthographicSize = Screen.height / (2z)`, позиция камеры округляется до `1/z` юнита (пиксели не плавают).
- Старт партии: зум 1:1, центр на столице человека.
- Колесо: шаг зума, точка под курсором остаётся на месте. Перетаскивание: ПКМ или средняя кнопка. ПКМ без сдвига больше 4 px — по-прежнему «отмена». Стрелки — сдвиг на 1/4 экрана за нажатие, Home — к своей столице.
- Клик по строке «Фронты» или по карточке сводки: камера едет к точке за 0,25 с (`unscaledDeltaTime`, пауза не мешает); с зума ½ переходит на 1:1.
- Центр камеры зажат в пределах карты.

### 5.6. Координаты

- `CellToWorld(x, y)` — центр верхней грани: `(x·S + S/2, (H·S + PAD) − (y·S + PAD − off + S/2))` (переворот, текстура снизу вверх). Им ставятся значки, подписи, выноски.
- `ScreenToCell`: экран → мир → пиксель текстуры → CPU-копия `CellId`. Небо → нет клетки, вода → клетка без владельца. Старый `WorldToPixel` заменяется этим везде, где был клик по карте.

### 5.7. Значки и подписи (UI Toolkit, слой `markers`)

Позиции пересчитываются в `LateUpdate` через `Camera.WorldToScreenPoint(CellToWorld(...))`, элементы переиспользуются (пул), без выделений в кадре.
- **Столица:** значок-звезда 32×32 цвета нации с тёмной обводкой.
- **Подпись страны:** имя (без формы) Tiny5 20 с тёмной обводкой 2 px, на 28 px выше звезды столицы. У человека «Альвария · вы». На зуме ½ — кегль 20, на 1:1 и ×2 — 30.
- **Штаб на фронте и «фронт открыт»** — те же точки, что считает `GameHud.UpdateMarkers` сейчас, новые значки (флажок с числом соединений, стрелка при наступлении; пустой круг у открытого).

## 6. Пример расчёта

**Запекание одной клетки.** Клетка `(100, 50)`, `Terrain = Hills`, `Elevation = 180`. По карте у холмов `eMin = 150`, `eMax = 199`, `bandLevels.hills = [2, 3]`.
`L = 2 + (180 − 150) · 2 / 50 = 2 + 1 = 3` → `off = 16`. Южный сосед `(100, 51)` — равнина, `L = 1`, `off = 5`.
Верх: `by ∈ [50·6 + 44 − 16, … + 5] = [328, 333]`, `bx ∈ [600, 605]`. Стена: `[334, 51·6 + 44 − 5 − 1] = [334, 344]`, 11 px = 16 − 5. Верх южной клетки начинается с 345. Цвет верха `Hills #829456` × (1 + 0,035·3) = ×1,105 ± шум.

**Тонировка одного пикселя.** Зум 1:1, пиксель верха этой клетки, владелец — Федерация Кесталь `(232, 138, 46)`, не человек. `base = (130, 148, 86)`, `luma(base) = 135,6`, `luma(nation) = 155,6`, `t = 0,871 · (232, 138, 46) = (202, 120, 40)`. `s = 3600 · 10 000 / 10 000 = 36%`. `col = base + 0,36·(t − base) = (156, 138, 70)`. Холм остаётся холмом, но рыжеватым.

**Граница.** Тот же пиксель, зум 1:1, сосед справа на 1 экранный px принадлежит Ольстрану, пара в войне: `d = 1 ≤ linePx` → пиксель красится в `#14121A`. Пиксель на 2 px левее границы: `d = 2`, `linePx < 2 ≤ 1 + 2` → кайма цветом Кесталя +25% к светлоте.

## 7. Цена по CPU и GPU

- **Ядро:** +2 слоя по 131 072 байт (256 КБ), генерация +≤ 30 мс (шум влажности), хеш +262 КБ на контрольную точку в `HashJob`. Тик не меняется, бюджет ≤ 0,25 мс должен остаться как в отчёте (0,054 мс в среднем).
- **Запекание:** 4,85 млн пикселей земли + ~25–35 тыс. спрайтов. Цель ≤ 300 мс на ноутбуке, писать время в `Player.log` (`bake ms`). Не уложились — записать цифру и сказать, не подгонять.
- **Память:** `TerrainColor` 19,4 МБ + мип 4,9, `CellId` 19,4 МБ, CPU-копия `CellId` 19,4 МБ. На ПК пустяк, Android — этап 5 (brief-02: запасной план 4 px на клетку, `cellPx` — ручка).
- **Кадр:** на пиксель 1 выборка цвета, 1 `CellId`, 1 владелец, до 4·3 = 12 пар (`CellId` + владелец) для границы, 1 FrontFx. На ПК запас большой (сейчас 180 fps). Значков ≤ ~100 UI-элементов.

## 8. Входы и выходы к другим системам

- Из ядра рендер читает `Owner` (каждый тик, грязные строки, как сейчас), `Terrain`, `Elevation`, `Biome` (раз за партию), нации, соединения и фронты (для панелей, как сейчас).
- `_PairStatus` — заготовка под статусы войны и мира куска 2 «Война, цели и мир». Там ядро начнёт хранить статус пары, и `Game` будет писать его в текстуру.
- `CellToWorld` и пул значков — заготовка под города куска 4 (значок города и точки зданий).
- `-bench`, `-benchShot`, `-replay` работают как раньше: бенч гоняет новую карту, реплей бенча проходит `HeadlessRunner -replay`.

## 11. Edge cases

- **Высокая южная клетка закрывает северную целиком** (`off(юг) − off ≥ S`): северная клетка не видна и не кликается. Фронт за ней всё равно видно по видимым пикселям соседей. Доля невидимых клеток суши — в тест 12.3; больше 1% — уменьшить `terraceOffsets`, не менять алгоритм.
- **Полоса пуста** (`hillsShare_bp = 0`): `eMin`, `eMax` не определены, уровень не считается, клеток нет — без деления на ноль.
- **Горы у северного края:** `PAD = 44` вмещает самый высокий уровень, выход за верх текстуры невозможен; тест на `CellId` ряда 0.
- **Экран ниже 1080** (`k = 1`): вся карта на ½ — 1536 px, может не влезть по ширине на 1366. Допустимо, перетаскивание работает.
- **Смена размера окна:** пересчитать `k`, зумы, масштаб `PanelSettings`, сохранить центр.
- **Тёмно-синий Вестмарк у океана:** тонируется только суша, граница по коду пикселей. Проверка серым (12.6) обязательна именно для него.
- **Нация пала:** её столица и подпись пропадают в тот же кадр, что и сейчас значок.
- **Пикинг по стене обрыва** даёт северную (верхнюю) клетку — та, чья стена. Так и задумано.
- **Пауза:** камера, наведение, плашки и сводка работают на паузе (unscaled time).
- **Реплей и детерминизм:** рендер не участвует. Старые реплеи получат код 2 (другой `dataHash`), это ожидаемо и пишется в описании PR.

## 12. Acceptance criteria

1. Для сидов 1–20 `Owner`, `Terrain` и столицы на тике 0 совпадают с `main` до изменения (эталонный хеш этих трёх массивов записывается тестом на первом коммите PR, до правок `MapGen`).
2. `Elevation` согласован с полосами: для каждой пары клеток суши из разных полос корзина более высокой полосы не меньше. `Biome` детерминирован и не зависит от потока `MapGen` (смена ручек `biomes` не меняет `Owner`, `Terrain`, столицы).
3. Запекание: уровень каждой клетки лежит в диапазоне своей полосы (`plains` = 1, `hills` 2–3, `mountains` 4–6); маска «вид = верх» по клеткам совпадает с маской полос пиксель в пиксель на 20 сидах; невидимых клеток суши ≤ 1%; пикселей с `CellId` за пределами карты нет.
4. Запекание детерминировано: два запуска с одним сидом дают байт в байт одинаковые `TerrainColor` и `CellId`.
5. Время запекания записано в `Player.log`; цель ≤ 300 мс (цифра в описании PR как есть).
6. На скриншоте всей карты (`-benchShot`, зум ½), переведённом в серое, видна каждая граница между государствами, включая Вестмарк. Проверяет Никта глазами.
7. Свою страну находишь за ≤ 2 с на любом зуме (Никта, 3 попытки на разных сидах).
8. Граница рисуется поверх деревьев, толщина линии 2 экранных px на всех трёх зумах (скриншот ×2 в описании PR).
9. Клик по карте попадает в ту клетку, на чей пиксель нажали, на всех зумах (EditMode-тест `ScreenToCell` на синтетических `CellId` + ручная проверка по плашке фронта).
10. Ни одного GameObject на клетку, дерево, значок или подпись (проверка иерархии сцены во время партии).
11. `-determinism 42` проходит, все EditMode-тесты зелёные, `CoreHasNoForbiddenApis` зелёный, средний тик в отчёте 100 партий не вырос (сейчас 0,054 мс).
12. `BattlePix.exe -screen-fullscreen 0 -bench 15 -benchSpeed 4` на ноутбуке ≥ 60 fps, реплей бенча проходит `-replay`.
13. В интерфейсе нет сырых строк отладки: ни «— : 1», ни «оборона 40 / 50 / 60 на ребро» в основном тексте (только в подсказках по наведению), стандартных серых кнопок Unity нет.
14. **Главное:** Никта играет 10 минут на билде после PR 15 и говорит «играбельно». Нет — правим картинку по замечаниям Никты, кусок 2 не начинаем.
