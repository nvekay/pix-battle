## 3. Данные

### 3.1. Типы дивизий (`rules.divisions`, массив, индекс = тип, не больше 8)

| Поле | Тип | Пехотная (0) | Танковая (1) |
| --- | --- | --- | --- |
| `id` | string | `infantry_div` | `armor_div` |
| `composition` | int[units] — батальонов каждого типа | [3, 0] | [1, 2] |
| `trainTicks` | int | 300 | 300 |

Цена дивизии = Σ `composition[u] × units[u].cost_c` (450 и 950). Содержание = Σ `composition[u] × units[u].upkeep_c` (0,3 и 0,7 в секунду). Отдельных полей цены нет: правка баланса батальона сразу меняет дивизию. `Validate`: состав не пустой, длина равна `units.Length`.

### 3.2. Состояние мира

`struct Division` (слот `(owner − 1) × maxDivisionsPerNation + k`; `k` — номер у нации, игрок видит «k + 1-я»):

| Поле | Тип | Что это |
| --- | --- | --- |
| `Owner`, `Alive`, `Type` | `byte` | |
| `Front` | `byte` | id противника, 0 — тыл |
| `ReadyTick` | `int` | до этого тика дивизия готовится (в тылу, силы не даёт); 0 — готова |
| `ArriveTick` | `int` | до этого тика в пути; 0 — на месте |
| `Strength_bp` | `short` | численность 0..10 000 |
| `Org_bp` | `short` | организация 0..10 000 |
| `Exhausted` | `byte` | 1 — выдохлась: не наступает до восстановления |

`NationState` дописать: `Divisions : byte` (живых), `RecruitedInfDiv`, `RecruitedArmorDiv`, `DivisionsLost : int`.

`FrontOrder : NativeArray<byte>` `N × N`, `[(a − 1) × N + (d − 1)]` — приказ стороны `a` на фронте с `d`: 0 оборона (по умолчанию), 1 наступление. Хранится и когда фронта нет.

`DivisionsArr : NativeArray<Division>` `N × maxDivisionsPerNation`.

Чтение наружу: `DivisionAt(slot)`, `DivisionSlot(owner, k)`, `FrontOrderOf(a, d)`, `OnFront(in Division)` = живая, `Front ≠ 0`, `ReadyTick ≤ Tick`, `ArriveTick ≤ Tick`; `Attacking(in Division)` = `OnFront` и `FrontOrderOf(owner, Front) == 1` и `Exhausted == 0`.

### 3.3. Команды

```csharp
RecruitDivision = 8,   // A = тип дивизии, B не используется
AssignDivision  = 9,   // A = k, B = id противника (0 — в тыл)
SetFrontOrder   = 10,  // A = id противника, B = 0 оборона / 1 наступление
// RejectReason дописать: DivisionInvalid = 22, DivisionLimit = 23, DivisionTypeInvalid = 24
```

- **RecruitDivision.** Нация жива; `0 ≤ A < divisions.Length` (`DivisionTypeInvalid`); `Divisions < maxDivisionsPerNation` (`DivisionLimit`); `Gold ≥ цена` (`NotEnoughGold`). Применение: первый свободный слот, `Front = 0`, `ReadyTick = Tick + trainTicks`, `ArriveTick = 0`, `Strength_bp = Org_bp = 10 000`, `Exhausted = 0`, счётчики.
- **AssignDivision.** Дивизия живая и своя (`DivisionInvalid`). `B = 0`: `Front = 0`, `ArriveTick = 0` сразу. `B ≠ 0`: противник жив и `≠ Nation` (`TargetInvalid`), `FrontLen[Nation, B] > 0` (`NoContact`), `B ≠ Front` или дивизия ещё в пути (`AlreadyThere`). Применение: `Front = B`, `ArriveTick = max(Tick, ReadyTick) + transferTicks`. Готовящуюся можно назначить заранее: уйдёт, как только будет готова.
- **SetFrontOrder.** `1 ≤ A ≤ N`, `A ≠ Nation`, противник жив (`TargetInvalid`); `B ∈ {0, 1}` (`OrderInvalid`). Общий фронт не обязателен: приказ можно поставить заранее.

UI для выделенной пачки шлёт по одной `AssignDivision` на дивизию в один тик, порядок — по `k`.

Вместо пунктов 2–4 spec-01b §4.5: нации (`Id`, `Alive`, `Capital`, `Pixels`, `Gold`, `Divisions`, `DiedAtTick`, `RecruitedInfDiv`, `RecruitedArmorDiv`, `DivisionsLost`); `DivisionsArr` по слотам все поля; `FrontOrder` целиком. ## 4. Правила и формулы

### 4.1. Сила сторон (`DivisionSystem.FillPow`, каждый тик до фазы A)

Для дивизии `v` типа `t`, рельефа `tr`:

```
atk100(v,tr) = Σ_u composition[t][u] × attack[u]  × 100 × attackTerrain_bp[u][tr]  / 10000      // по батальонам, деление на каждом шаге
def100(v,tr) = Σ_u composition[t][u] × defense[u] × 100 × defenseTerrain_bp[u][tr] / 10000
orgMult(v)   = orgDefenseMin_bp + (10000 − orgDefenseMin_bp) × Org_bp / 10000

att100(a,d,tr) = Σ_{v: Attacking, Front = d}  atk100(v,tr) × Strength_bp / 10000
def100(a,d,tr) = Σ_{v: OnFront,   Front = d}  def100(v,tr) × Strength_bp / 10000 × orgMult(v) / 10000 × (Attacking(v) ? attackingDefense_bp : 10000) / 10000
attPow, defPow — как 01b §5.1 (деление на FrontLen, гарнизон, terrainDefense_bp)
```

`atk100`/`def100` по типу и рельефу считаются один раз при загрузке правил (таблица 8 × 3).

### 4.2. Организация (`DivisionSystem`, раз в секунду, после экономики, до потерь)

`A(a,d)`, `D(d,a)` — как 01b §5.3. Для каждой живой готовой дивизии по слотам:

```
если Attacking(v) и A(a,d) > 0:   Org −= attackOrgLoss_bp  × clamp(D(d,a) × 10000 / A(a,d), lossRatioMin_bp, lossRatioMax_bp) / 10000
иначе если OnFront(v) и A(d,a) > 0: Org −= defendOrgLoss_bp × clamp(A(d,a) × 10000 / max(D(a,d),1), lossRatioMin_bp, lossRatioMax_bp) / 10000
иначе: Org += OnFront(v) ? orgRecoverFront_bp : orgRecoverRear_bp      // тыл, путь, подготовка — «тыл»
Org = clamp(Org, 0, 10000)
если Org < haltOrg_bp: Exhausted = 1;   если Exhausted и Org ≥ resumeOrg_bp: Exhausted = 0
```

Под ударом в обороне дивизия восстанавливаться не может. Выдохшаяся дивизия на фронте с приказом «наступление» не атакует, держит без штрафа `attackingDefense_bp` и восстанавливается, если на неё не давят.

### 4.3. Потери и пополнение

Как 01b §5.3, но объект — дивизия, а не батальон: `loss` считается теми же формулами по `Attacking(v)` и «на нас наступают», вычитается из `Strength_bp` дивизии. Пополнение: `rate` — `reinforceRear_bp` в тылу, в пути и в подготовке, иначе `reinforceFront_bp`; `price = ценаДивизии × add / 10000 × reinforceCostMult_bp / 10000`. Дивизия с `Strength_bp ≤ 0` гибнет (`Alive = 0`, `Divisions −= 1`, `DivisionsLost += 1`).

### 4.4. Экономика

`upkeep_c = Σ живые дивизии (включая готовящиеся) содержание типа`. Дезертирство при `Gold < 0`: дивизия с наименьшей `Strength_bp` (равенство — больший слот) теряет `desertLoss_bp`, `Gold = 0`; на нуле гибнет.

### 4.5. Закрытие фронта и гибель нации

Как 01b §5.5: дивизия с `Front = d` уходит в тыл, если фронта с `d` нет или `d` мёртв. Гибель нации: её дивизии `Alive = 0`, строка и столбец `FrontOrder` обнуляются.

### 4.6. Порядок тика

Как 01b §5.6, `FormationSystem` → `DivisionSystem`. Порядок секунды: доход и содержание → дезертирство → организация → потери → пополнение.

### 4.7. Старт

`startDivisions` = [1, 0]: одна пехотная, готова, в тылу, `Org = Strength = 10 000`.

### 4.8. ИИ (`AiSystem`, одна команда за раз)

Оценки `threat(d)`, `plainShare(d)`, `opp(d)`, `target` — как 01b §5.8; `opp` считается по всем своим готовым дивизиям, как если бы все наступали на `d`. Правила сверху вниз:

1. **В тыл обескровленную.** Дивизия на фронте с `Strength < rearStrength_bp`, на её фронте `threat < threatRatio_bp` → `AssignDivision 0`.
2. **Закрыть прорыв.** Фронт с `threat ≥ threatRatio_bp` без своих дивизий на месте и в пути → туда готовую дивизию из тыла с `Strength ≥ deployStrength_bp` и `Org ≥ resumeOrg_bp`; если в тылу нет — одну с фронта с наименьшим `threat`, кроме `target`.
3. **Ротация.** На `target` есть выдохшаяся дивизия, а в тылу свежая (`Org ≥ resumeOrg_bp`, `Strength ≥ deployStrength_bp`, готова) → свежую на `target`. Следующей мыслью — выдохшуюся в тыл, если `threat(target) < threatRatio_bp`.
4. **Кулак.** Свежая готовая дивизия в тылу → на `target`. Готовящуюся не трогает.
5. **Приказы.** `FrontOrder(self, target)` = 1, если `opp(target) ≥ attackMinRatio_bp`, иначе 0; на остальных фронтах 0. Одна команда, если приказ расходится с нужным.
6. **Набор.** Танковая, если `plainShare(target) ≥ armorPlainShare_bp` и доля танковых среди живых `< armorMaxShare_bp`, иначе пехотная; только если золото ≥ цены + `recruitReserve_c`.

Профили: `base`; `spread` — правила 2–5 заменены на «готовую дивизию из тыла — на фронт с наименьшей суммой `def100` на ребро, все приказы — наступление»; `no_armor` — `armorPlainShare_bp = 1 000 000`.

## 5. Пример расчёта

Красные против Синих, `FrontLen = 120`, рельеф синих пикселей 72 / 36 / 12. Ручки — раздел 8. Все готовы, на месте, численность 100%.

Таблица типа (пехотный батальон: атака 1 000, оборона 1 400 в ×100; бронетанковый: атака 3 380 / 2 080 / 1 040, оборона 1 400 / 1 120 / 700 по рельефу):

| | `atk100` равн. / холм. / горы | `def100` равн. / холм. / горы |
| --- | --- | --- |
| Пехотная [3, 0] | 3 000 / 3 000 / 2 700 | 4 200 / 4 200 / 4 200 |
| Танковая [1, 2] | 7 760 / 5 160 / 2 980 | 4 200 / 3 640 / 2 800 |

Красные: 2 танковые + 2 пехотные, наступление, `Org` 100%. Синие: 3 пехотные, оборона, `Org` 100%.

| | Равнина | Холмы | Горы |
| --- | --- | --- | --- |
| `att100` Красных = 2 × танк. + 2 × пех. | 21 520 | 16 320 | 11 360 |
| `attPow` = / 120 | 179 | 136 | 94 |
| `def100` Синих = 3 × 4 200 × orgMult 10 000 | 12 600 | 12 600 | 12 600 |
| `defPow` = (12 600 / 120 + 40) × рельеф | 145 | 181 | 217 |
| `ratio_bp` / `chance_bp` | 12 344 / **78** | 7 513 / **0** | 4 331 / **0** |

Секунда: `A = 179 × 72 + 136 × 36 + 94 × 12 = 18 912`, `D = 145 × 72 + 181 × 36 + 217 × 12 = 19 560`.
- Организация Красных: `150 × clamp(19 560 × 10 000 / 18 912 = 10 342) / 10 000 = 155` bp/с → выдохнутся примерно через 55 с.
- Организация Синих: `100 × 9 668 / 10 000 = 96` bp/с (`9 668 = 18 912 × 10 000 / 19 560`).
- Численность Красных: `50 × 10 342 / 10 000 = 51` bp/с, Синих — `20 × 9 668 / 10 000 = 19` bp/с.

Волна: к ~55-й секунде у Синих (грубо, без обратной связи) `Org ≈ 4 700`, `orgMult = 5 000 + 5 000 × 4 700 / 10 000 = 7 350`, `def100 = 12 600 × 7 350 / 10 000 = 9 261`, `defPow` = 117 / 146 / 175. Шанс Красных: равнина `179 × 10 000 / 117 = 15 299` → **131**, холмы `136 × 10 000 / 146 = 9 315` → **23**, горы **0**. Фронт ускоряется к концу волны, потом Красные выдыхаются и встают; Синие начинают восстанавливаться. Свежая пара дивизий из тыла в этот момент и рвёт фронт.

Тесты повторяют обе таблицы, три числа секунды и `orgMult` (acceptance 3–4). Точные значения «к 55-й секунде» тест считает пошагово сам, в спеке они приблизительные.

## 10. Edge cases

- Готовящуюся дивизию назначили — уходит в `ReadyTick`, прибывает через `transferTicks`; фронт закрылся до прибытия — в тыл.
- Приказ «наступление» на фронте без дивизий — ничего не делает, значок «пусто» остаётся.
- Все дивизии фронта выдохлись — фронт атакует нулём, держит по `orgMult`.
- `SetFrontOrder` на соседа без общей границы — принимается, хранится.
- Деньги кончились во время подготовки — дивизия всё равно будет готова (цена уже списана), содержание идёт.
- Выделение включает дивизию, уже стоящую на целевом фронте, — её команда отклоняется `AlreadyThere`, остальные проходят; UI не показывает это как ошибку.
- Реплей формата 3 — код 2.

2. Валидация: на `DivisionInvalid`, `DivisionLimit`, `DivisionTypeInvalid`, `NotEnoughGold`, `TargetInvalid`, `NoContact`, `AlreadyThere`, `OrderInvalid`, `Obsolete` (для 5, 6, 7) — тест, где команда отклоняется, а мир не меняется.
3. `DivisionPowTests` воспроизводят таблицу типов и первую таблицу раздела 5 с округлениями.
4. Секунда из раздела 5: организация −155 / −96, численность −51 / −19; гистерезис: ниже 1 500 выдохлась, на 5 999 ещё выдохлась, на 6 000 — нет; `orgMult` при 4 700 = 7 350.
5. Подготовка и путь: дивизия не даёт силы до `ReadyTick` и до `ArriveTick`; назначенная заранее прибывает в `ReadyTick + transferTicks`.
6. `FrontJob` с 1 потоком и со всеми — одинаковый хеш на сидах 1–10 через 3 000 тиков; `HashJob` = `HashManaged` на 10 мирах с дивизиями; `DerivedStateMatches` на сидах 1–10.
7. `-determinism 42` проходит; реплей из игры (≥ 20 команд трёх новых типов, включая пачку назначений в один тик) проходит `-replay`; подмена команды ловится; формат 3 — код 2.
8. `-seeds 1-100`: код 0, отчёт со строками раздела 7, средний тик ≤ 0,25 мс. Цели ворот не обязаны выполняться, отчёт честный.
9. `-profile 1=spread` и `1=no_armor` дают строки сравнения. Ожидание для описания PR: `base` побеждает чаще `spread` (в 1b было 16 против 3), `exhaustedTime_bp` и `rotations` у `base` не нулевые.
10. `-analyze` печатает фокус-эпизоды, наборы под рельеф и ротации.
11. В игре: набор обоих типов, плитки с таймером подготовки, выделение кликом, Shift и рамкой, назначение пачкой на фронт кликом по строке и по карте, «В тыл», переключатель приказа в «Фронтах», значок паузы на карте и в плашке; партия доходит до экрана конца.
