## 1. Цель и решение игрока

Сделать первую партию, в которую можно играть: континент из шума, 8 наций, расползание по пустой земле, войны соседей, золото с земли, три решения с ценой и конец партии. Это первые ворота «Весело?»: все три пиллара проверяются здесь.

Решения игрока (и только они, других кнопок влияния на мир нет):

| Решение | Цена | Что даёт |
| --- | --- | --- |
| Набрать батальон | 200 золота сразу и 0,25 золота/с содержания | +1 батальон, армия сама делится по фронтам |
| Поставить крепость | 400 золота, дальше по таблице (×1,5) | ×3 защиты в радиусе 16 px навсегда, пока пиксель крепости твой |
| Удар по соседу | 1 батальон сгорает | ×3 давления на фронт с этим соседом на 20 с |
| Копить | время | — |

Ключевая развилка: **за то же золото крепость держит свой участок лучше армии, но не наступает.** Если ни один плейтестер ни разу не выбрал крепость вместо армии, крутим числа из раздела 9, а не добавляем фичи.

## 3. Жёсткие правила этого этапа

1. Всё из CLAUDE.md. Особенно: в ядре только целые, деление к нулю, никаких `float`.
2. **Случайность фронта без порядка обработки.** Каждый пограничный пиксель решает свою судьбу по хешу `(соль тика, индекс пикселя, номер соседа)`, а не по очередному `Next()`. Поэтому фронт можно считать параллельным Burst-джобом, и результат не зависит от числа потоков. Соль тика — один `Next()` из потока `Front` в начале тика. Хеш — `Pcg32.Hash(uint)` (раздел 4.3), это часть нашего генератора.
3. **Двухфазный фронт.** Фаза A читает только состояние до тика и пишет решения в отдельный буфер. Фаза B последовательно применяет решения. Никакой пиксель не меняется в фазе A.
4. **ИИ — система ядра, которая отдаёт команды через ту же очередь** на `Tick + 1` (метод `CommandQueue.EnqueueInternal`). Такие команды не пишутся в лог реплея: в реплее ИИ сгенерирует их сам. В лог идут только команды человека (`Simulation.Enqueue` и `EnqueueFromUi`). Валидация и применение одинаковые для всех.
5. ИИ не читает ничего, кроме `World` и своих весов. Никакого знания о том, что делает человек, кроме видимого на карте.
6. Числа баланса — только в `rules.json` и `ai.json`. В коде нет ни одной константы баланса, кроме значений по умолчанию в DTO, которые совпадают с данными.

### 4.2. Состояние мира (дополнения к `World`)

Рельеф: `enum Terrain : byte { Water = 0, Land = 1 }`, значения только дописываются. Пиксель воды никогда не принадлежит нации и не бывает пограничным. В мире без правил (Фундамент) `Terrain` по-прежнему везде 0 и никто его не читает.

`NationState` (индекс = id − 1):

| Поле | Тип | Что это |

| `Capital` | `int` | индекс пикселя столицы; −1 у мёртвой |
| `Pixels` | `int` | сколько пикселей у нации, ведётся инкрементально |
| `Gold` | `int` | золото в сотых (100 = 1 золото), не меньше 0 |
| `Battalions` | `int` | число батальонов |
| `FortsAlive` | `byte` | сколько крепостей стоит сейчас |
| `DiedAtTick` | `int` | −1, пока жива |
| `Recruits`, `FortsBuilt`, `Strikes` | `int` | счётчики для отчёта |

Новые массивы `World` (все `Persistent`, освобождаются в `Dispose`):

| Поле | Тип | Что это |
| --- | --- | --- |
| `Forts` | `NativeArray<Fort>` длиной `nations × maxFortsPerNation` | `struct Fort { int Pixel; byte Owner; byte Alive; }`, слот `(owner − 1) × maxForts + k` |
| `FortCover` | `NativeArray<ushort>` 512×256 | битовая маска наций, чья живая крепость накрывает пиксель (бит `id − 1`); производное от `Forts`, пересчитывается кругом при постройке и падении крепости |
| `StrikeUntil` | `NativeArray<int>` `nations × nations` | `[a × N + d]` — тик, до которого (не включая) идёт удар `a` по `d`; 0 — удара нет |
| `FrontLen` | `NativeArray<int>` `(N + 1) × (N + 1)` | число рёбер между пикселями `a` и `d` по 4-соседству; симметрично; строка 0 — граница с ничьей землёй; пересчитывается каждый тик |
| `FlipHistory` | `NativeArray<short>` `10 × N × N` | кольцевой буфер: сколько пикселей `d` перешло к `a` за каждую из последних 10 секунд; ячейка секунды `(Tick / tps) % 10` |

| `TotalLand` | `int` | число пикселей суши после генерации |
| `Winner` | `byte` | победитель, 0 — нет |

Все поля открыты наружу только на чтение (`ReadOnly`-обёртки или методы `FrontLength(a, d)`, `ArmyOnFront(a, d)`, `NetFlips10s(a, d)`), пишут только системы ядра. `ArmyOnFront` считается формулой 5.4 из текущего состояния, не хранится.

`EndReason` дописать: `Conquest = 2` (кто-то взял порог суши или остался один), `Timeout = 3` (таймер правил), `HumanDefeated = 4` (пала столица человека). `TickLimit = 1` остаётся страховкой раннера.

### 4.3. Генератор

`RngStream` не меняется: `MapGen = 1` — генерация карты и столиц, `Front = 2` — соль тика фронта, `Ai = 4` — шум ИИ. Новых потоков не нужно.

Добавить `public static uint Pcg32.Hash(uint v)` — PCG-хеш (вариант RXS-M-XS 32 из pcg-c, тот же, что «pcg_hash» у Jarzynski и Olano, 2020):

```
state = v * 747796405u + 2891336453u;
word  = ((state >> (int)((state >> 28) + 4u)) ^ state) * 277803737u;
return (word >> 22) ^ word;
```

Случайное число фронта для пикселя `t` и соседа `k` (0..3): `Pcg32.Hash(salt ^ Pcg32.Hash((uint)t * 4u + (uint)k)) % 10000`, где `salt = Front.Next()` в начале тика. Посчитай 3 тестовых вектора эталонной реализацией и положи в тест. Я их не привожу: проверить их сейчас мне нечем, а цифры по памяти в тест класть нельзя.

### 4.4. Команды

```csharp
public enum CommandType : byte {
    Noop = 0, DebugSetOwner = 1,
    Recruit = 2,     // A, B не используются
    BuildFort = 3,   // A = индекс пикселя
    Strike = 4,      // A = id нации-цели
}
public enum RejectReason : byte {
    None = 0, PixelOutOfMap = 1, OwnerOutOfRange = 2, UnknownType = 3,
    NationInvalid = 4,     // Nation = 0, вне диапазона или мертва
    NotEnoughGold = 5, ArmyCap = 6,
    NotOwnPixel = 7, TooCloseToFort = 8, FortLimit = 9,
    NoBattalions = 10, TargetInvalid = 11, NoContact = 12,
    RulesDisabled = 13,    // игровая команда в мире без правил
}
```

Валидация (детерминированная, в момент применения):

- **Recruit:** нация жива; `Gold ≥ battalionCost`; `Battalions < battalionCap`. Применение: `Gold −= battalionCost`, `Battalions += 1`, `Recruits += 1`.
- **BuildFort:** нация жива; пиксель в карте, `Owner == Nation`; `FortsAlive < maxFortsPerNation`; ни одной своей живой крепости ближе `fortMinSpacing` (евклидово, сравнение квадратов); `Gold ≥ fortCost[FortsAlive]` (таблица, после её конца — последнее значение × 3 / 2 за каждый лишний шаг). Применение: списать, занять первый свободный слот, поставить биты `FortCover` в круге `fortRadius`, `FortsBuilt += 1`.
- **Strike:** нация жива; `1 ≤ A ≤ N`, `A ≠ Nation`, цель жива; `FrontLen[Nation, A] > 0`; `Battalions ≥ 1`. Применение: `Battalions −= 1`; `StrikeUntil[Nation, A] = max(StrikeUntil, Tick) + strikeDurationTicks`; `Strikes += 1`.

Команды одного тика применяются по `(Nation, Seq)`, как в Фундаменте: если на две покупки не хватает золота, вторая отклоняется.

## 5. Правила и формулы

### 5.1. Генерация карты (`MapGen`, один раз в конструкторе)

Цель: один континент, суша 47% карты (±2%), 8 столиц, честные старты.

1. **Шум.** Value noise на целых, 4 октавы. Октава `o`: шаг решётки `cell = 64 >> o` px, значения узлов 0..65535 из `MapGen.Next() & 0xFFFF`, узлы заполняются построчно. Значение пикселя — билинейная интерполяция по smoothstep в фиксированной точке: `t` в 0..1024, `s = t × t × (3072 − 2t) / 1048576`. Амплитуда октавы `65536 × persistence^o` (`persistence_bp = 5000`, считать умножением на `persistence_bp / 10000` по шагам). Сумма в `long`.
2. **Спад к краям.** `d` = расстояние до ближайшего края карты в px. Если `d < edgeFalloffPx` (24), вычесть `(edgeFalloffPx − d) × edgePenaltyPerPx` (4 000). Так суша не липнет к краям.
3. **Порог.** Гистограмма высот на 1 024 корзины (после нормировки в 0..1023), порог — первая корзина сверху, при которой суши ≥ `landShare_bp` (4 700). Выше порога — `Land`, ниже — `Water`.
4. **Один континент.** Заливка по 4-соседству (BFS по возрастанию индекса старта, очередь FIFO), остаётся только самый большой компонент суши, остальное — вода. Флота нет, острова не нужны.
5. Если суши после шага 4 меньше `minLandShare_bp` (4 000), повторить с шага 1, продолжая поток `MapGen`. Не больше 8 попыток, потом взять лучшую и пометить в отчёте `mapRetryFail`.
6. **Столицы.** Кандидат — пиксель суши, от которого до воды не меньше `capitalCoastDist` (6) px. Первая столица — случайный кандидат. Каждая следующая — лучший из 64 случайных кандидатов по максимуму минимального расстояния до уже поставленных (квадраты, без корней).
7. **Честность стартов.** Многоисточниковый BFS по суше от всех столиц (порядок источников — по id), размер «ячейки» каждой нации. Если `max/min > startFairnessMax_bp` (25 000, то есть 2,5×), переставить все столицы заново (шаг 6). Не больше 16 попыток, потом взять лучшую по отношению и пометить `unfairStart`.
8. **Стартовые пятна.** Каждой нации все пиксели суши в круге `startRadius` (8) px вокруг столицы, если они ещё ничьи (порядок наций по id). Это около 200 px.
9. Стартовые ресурсы: `startGold` (300 золота), `startBattalions` (3).

Бюджет генерации ≤ 200 мс в headless. Генерация входит в `World` до тика 0 и попадает в первый хеш.

### 5.2. Порядок тика (пайплайн с правилами)

1. Команды тика, как в Фундаменте (валидация по 4.4).
2. `FrontSystem`: соль, фаза A (Burst), фаза B, `FrontLen`, `FlipHistory`, падение крепостей и столиц.
3. `EconomySystem`: раз в секунду (`Tick % tps == tps − 1`) доход, содержание, дезертирство.
4. `StrikeSystem`: обнулить истёкшие `StrikeUntil` (`≤ Tick + 1`) и удары по мёртвым или от мёртвых.
5. `AiSystem`: думает каждая ИИ-нация раз в `thinkIntervalTicks` (10) со сдвигом `(id − 1) % thinkIntervalTicks`, отдаёт команды на `Tick + 1`.
6. `EndSystem`: проверка конца (5.7).
7. `Tick += 1`, лимит, контрольная точка — как в Фундаменте.

### 5.3. Пограничные пиксели

Пиксель `t` пограничный, если это суша и хотя бы один из 4 соседей — суша с другим владельцем (включая ничью землю). Ничьи пиксели тоже бывают пограничными: их захватывают при расползании.

`Frontier` строится полным проходом после генерации и после каждой гибели нации. В обычном тике в фазе B: для каждого перешедшего пикселя проверить его и 4 соседей, добавить в список тех, кто стал пограничным. Удаление ленивое: в начале фазы A список уплотняется, выкидываются записи, которые больше не пограничные (`InFrontier` сбрасывается). Порядок списка не влияет на результат (правило 3.2), но должен быть детерминированным: он и так строится последовательно.

### 5.4. Давление на фронте

Для пары наций `a`, `d` с `FrontLen[a, d] > 0`:

```
warLen(a)        = Σ FrontLen[a, x] по живым x ≠ a, x ≠ 0     // граница с ничьей землёй армию не ест
armyOnFront(a,d) = Battalions(a) × 1000 × FrontLen[a,d] / warLen(a)   // милли-батальоны
pow(a,d)         = armyOnFront(a,d) / FrontLen[a,d] + garrisonPerEdge  // плотность на ребро
```

Атака `a` на пиксель `t` нации `d`:

```
att      = pow(a,d) × (StrikeUntil[a,d] > Tick ? strikeMult : 1)
defMult  = 1 × (fortMult, если в FortCover[t] стоит бит d) × (capitalMult, если t в круге capitalRadius от столицы d)
defMult  = min(defMult, defenseMultCap)
def      = pow(d,a) × defMult
ratio_bp = att × 10000 / def
chance   = clamp(warChance_bp × (ratio_bp − stallRatio_bp) / 10000, 0, maxChance_bp)
```

Множители хранятся в базисных пунктах (`strikeMult_bp = 30000`), умножение `x × m_bp / 10000`. Ничья земля: `chance = expandChance_bp` от любого соседа-нации, армия не важна.

Смысл формулы: при равной плотности (`ratio` = 1,0) обе стороны отъедают друг у друга по чуть-чуть, граница дрожит на месте. Сдвиг дают перевес плотности, удар и крепость. Отсюда ровно четыре причины, которые игрок должен уметь назвать.

### 5.5. Фронт за тик

**Фаза A** (`FrontJob : IJobParallelFor` по `Frontier`, Burst): для пиксель-цели `t` с владельцем `d` перебрать соседей в порядке N, E, S, W (`k` = 0..3). Для каждого соседа-нации `a ≠ d` (живой, на суше) посчитать `chance` и `roll = hash(salt, t, k)`. Первый сосед с `roll < chance` забирает пиксель: `Decision[i] = a`, иначе 0. Сосед, который уже встречался на этом пикселе, второй раз не бросает. Вода и края карты пропускаются. Джоб читает только `Owner`, `FortCover`, массив `pow` по парам (посчитан до джоба), столицы, `StrikeUntil`.

**Фаза B** (последовательно, по порядку `Frontier`):

1. Для каждого `Decision[i] ≠ 0`: `SetOwner`, `Pixels` −/+, `FlipHistory[сек][a][d] += 1` (для ничьей земли не пишется), отметить соседей для `Frontier`.
2. Если на перешедшем пикселе стояла живая крепость прежнего владельца — крепость пала: `Alive = 0`, `FortsAlive −= 1`, пересчитать круг `FortCover` по оставшимся крепостям этой нации.
3. Если перешедший пиксель — чья-то столица, нация пала. Гибель обрабатывается после всех переходов тика, по возрастанию id: все её пиксели → 0, крепости сняты, `Battalions = 0`, `Gold = 0`, `Alive = 0`, `Capital = −1`, `DiedAtTick = Tick`, удары от неё и по ней обнулены, `Frontier` и `FrontLen` строятся полным проходом. Пиксели, которые другие нации забрали в этом же тике, остаются у них.
4. `FrontLen` пересчитать по `Frontier`: для каждого пограничного пикселя посчитать рёбра только к соседям E и S, если у соседа другой владелец (и это суша). Оба конца межнационального ребра всегда пограничные, поэтому каждое ребро посчитано ровно один раз. Записать в обе ячейки `[a,d]` и `[d,a]`. Тест сверяет с полным проходом по карте.
5. В начале каждой новой секунды ячейка `FlipHistory` этой секунды обнуляется.

`NetFlips10s(a, d)` = сумма по 10 ячейкам `[a][d] − [d][a]`. Положительное — `a` наступает.

### 5.6. Экономика (раз в секунду)

```
income_c = flatIncome_c + Pixels × 100 / pixelsPerGold      // в сотых
upkeep_c = Battalions × upkeep_c_per_battalion
Gold    += income_c − upkeep_c
если Gold < 0: Battalions −= 1 (если есть), Gold = 0            // дезертирство, одно за секунду
```

Стартовые числа: `flatIncome_c = 200`, `pixelsPerGold = 2000`, `upkeep_c_per_battalion = 25`. У мёртвой нации ничего не считается.

### 5.7. Конец партии (`EndSystem`)

Проверки по порядку, первая сработавшая заканчивает партию (`IsOver = true`):

1. Человек есть и его нация мертва → `HumanDefeated`, `Winner = 0`.
2. Живая нация с `Pixels × 10000 ≥ victoryShare_bp × TotalLand` → `Conquest`, `Winner` = она. Если таких несколько — с большим `Pixels`, при равенстве меньший id.
3. Жива только одна нация → `Conquest`, `Winner` = она.
4. `Tick + 1 ≥ timeoutTicks` → `Timeout`, `Winner` = живая нация с наибольшим `Pixels` (равенство — меньший id).

Для человека: победа, если `Winner == human`; поражение во всех остальных случаях, включая победу ИИ по порогу и таймер не в его пользу.

### 5.8. ИИ-заглушка (`AiSystem`)

Один профиль весов `base` для всех ИИ-наций. Характеров нет (срез), но формат `ai.json` уже держит несколько профилей, чтобы делать абляции (9.6). Думает нация так, сверху вниз, и отдаёт **не больше одной команды** за раз:

1. **Крепость под давлением.** Худший фронт `d` = минимум `NetFlips10s(self, d)`. Если он ≤ `−fortLossThresholdPx`, на этом фронте нет своей крепости (ни один пограничный пиксель нации на фронте с `d`, найденный в выборке, не накрыт своим битом) и хватает золота — `BuildFort`. Пиксель: до 32 попыток взять случайный (поток `Ai`) пиксель `Frontier` своей нации, соседний с `d`, сдвинуть его на `fortDepthPx` (6) по прямой к своей столице (Брезенхем, целые), остановиться на последнем своём пикселе. Первый валидный по 4.4 идёт в команду.
2. **Копить на крепость.** Если пункт 1 сработал бы, но не хватает золота, — ничего не делать (так ИИ сам «не набирает армию, потому что золото нужнее»).
3. **Набор.** Если `Battalions × 1000 < targetDensity_milli × warLen / 100` (цель на 100 рёбер войны) или `Battalions < minBattalions`, и хватает золота с запасом `recruitReserve_c` — `Recruit`.
4. **Удар.** Если `Battalions ≥ strikeMinBattalions` и сейчас нет своего активного удара: для каждого соседа `d` `score_bp = pow(self,d) × 10000 / pow(d,self)`, плюс `leaderBonus_bp`, если доля `d` от `TotalLand` ≥ `leaderShare_bp`, плюс шум `Ai.NextInt(noise_bp + 1)`. Если лучший `score_bp ≥ strikeMinScore_bp` — `Strike` по нему.

Пункт 4 с `leaderBonus` — тормоз snowball из брифа (догпайл на лидера). Он работает через ту же команду, отдельной логики «против лидера» нет.

## 6. Пример расчёта на одном тике

Две нации: 1 (Красные) и 2 (Синие), общий фронт `FrontLen[1,2] = 120` рёбер. У Красных 12 батальонов и `warLen = 300` (ещё фронт с третьей нацией). У Синих 8 батальонов и `warLen = 160`. `garrisonPerEdge = 10`, `warChance_bp = 180`, `stallRatio_bp = 8000`, `maxChance_bp = 800`, `defenseMultCap_bp = 40000`.

- `armyOnFront(1,2) = 12 × 1000 × 120 / 300 = 4 800`, `pow(1,2) = 4800 / 120 + 10 = 50`.
- `armyOnFront(2,1) = 8 × 1000 × 120 / 160 = 6 000`, `pow(2,1) = 6000 / 120 + 10 = 60`.

Шанс Красных забрать синий пиксель `t`:

| Ситуация | att | def | ratio_bp | chance_bp |
| --- | --- | --- | --- | --- |
| Без всего | 50 | 60 | 8 333 | 180 × 333 / 10000 = **5** |
| Удар Красных | 150 | 60 | 25 000 | 180 × 17 000 / 10000 = 306 → **306** |
| Синяя крепость | 50 | 180 | 2 777 | **0** |
| Удар против крепости | 150 | 180 | 8 333 | **5** |
| Крепость + столица Синих (×6 → кап ×4) | 150 | 240 | 6 250 | **0** |

Обратно, Синие по красному пикселю без всего: `ratio = 60 × 10000 / 50 = 12 000`, `chance = 180 × 4 000 / 10000 = 72`. Без ударов фронт ползёт к Красным примерно на 1,4 px за 20 с. Красный удар разворачивает его: 306 против 72 bp, это около 4,7 px вглубь за 20 с удара. Синяя крепость в ответ гасит удар до 5 bp: вот она, причина «почему встал фронт».

Решение по пикселю: `roll = hash(salt, t, k)` из 4.3; пиксель переходит, если `roll < chance_bp`. Конкретный пример с реальным `salt` и значениями хеша агент собирает сам по 4.3 и кладёт в `FrontExampleTests` (acceptance 6).

Экономика Красных в конце той же секунды: `Pixels = 8 000`. `income_c = 200 + 8000 × 100 / 2000 = 600`, `upkeep_c = 12 × 25 = 300`, `Gold += 300` (3 золота/с). Следующий батальон через ~67 с, крепость через ~133 с. Это и есть давление выбора.

## 7. Тик и цена по CPU

- 10 тиков/с на ×1, таймер 27 000 тиков = 45 мин. Ожидаемая длина партии 25–45 мин.
- Фронт: ~3–8 тыс. пограничных пикселей. Фаза A — Burst-джоб, батч 256. Фаза B и `FrontLen` — последовательно, в Burst `IJob`.
- Гибель нации — полный проход по карте, 1 раз на нацию за партию.
- ИИ: 8 наций, каждая раз в секунду, без проходов по всей карте (только выборки из `Frontier`).
- **Бюджет:** средний тик ≤ 0,4 мс, p99 ≤ 2 мс в headless на ПК разработчика (контрольные точки не в счёт). 100 партий по ~25 000 тиков укладываются примерно в 17 минут. Если не укладывается, пишем как есть в отчёт, цифры не подгоняем, профилируем.
- Игра на ПК в 1080p держит 60 fps на ×4 с 8 нациями. На Android не меряем (ворота 4).

## 8. Входы и выходы к другим системам

**Отдаёт срезу (этап 2):** `CommandType` для мира и целей войны; `FlipHistory` и `NetFlips10s` для бунтов и уведомлений; профили `ai.json` — каркас характеров; `EndReason` — сюда допишется распад; `Terrain` — сюда допишется рельеф (этап 3).

**Принимает:** четыре строки JSON, сид, `humanNation`, команды человека.

**Headless-раннер.** Новые флаги:

- `-human <id>` — нация под человеком для `-replay` (по умолчанию из файла) и для отладки; в обычном прогоне 0.
- `-profile <nationId>=<profile>` — назначить нации профиль из `ai.json` (абляция: `-profile 1=no_forts`).
- `-analyze <replay>` — разбор партии человека (см. ниже).

`MatchResult` дополнить: `EndReason`, `Winner`, `EndTick`, `EndMinutes`, доля лидера на 10/20/30 минуте (bp от `TotalLand`), `FirstContactTick`, `StartFairness_bp` (max/min `Pixels` на тике 3000), флаги `mapRetryFail` и `unfairStart`, по нациям: `DiedAtTick`, `Recruits`, `FortsBuilt`, `Strikes`, профиль.

`report.md` дополнить сводкой ворот 1, каждая строка с целью и «ок»/«провал»:

| Строка | Цель |
| --- | --- |
| Партии с концом (`Conquest`, `Timeout`, но не `TickLimit` и не крах) | 100% |
| Длина 25–45 мин | ≥ 80% партий |
| Конец до 10-й минуты | 0 партий |
| Доля лидера на 10-й минуте | ≤ 25% в ≥ 90% партий |
| Партии по таймеру | ≤ 10% |
| Честность стартов (max/min на 5-й минуте) | ≤ 2,0× в ≥ 90% партий |
| Победы одного id нации | ≤ 25% (ожидание 12,5%, ловим перекос позиций) |
| Средний и p99 тик | ≤ 0,4 / ≤ 2 мс |

Если прогон с `-profile` — отдельная строка «победы профиля X у нации N» против прогона без абляции.

**`-analyze <replay>`** печатает и пишет `analysis.md` по партии человека: исход и минута, число принятых команд по типам, решений за первые 10 минут (цель ≥ 5), сколько раз человек поставил крепость, хотя в момент покупки у него хватало на батальон и хватало уже ≥ 10 с (`fortOverArmy`, цель ≥ 1). Это машинная половина метрики ворот 1, вторая половина — вопрос на плейтесте.

## 10. UI

Экран один: карта и игровой HUD. Отладочная панель Фундамента остаётся, но открывается кнопкой «⚙» и по умолчанию скрыта. UI Toolkit, `PanelSettings` из Фундамента, все цели не меньше 44×44.

**Карта.** Шейдер `OwnerPalette` дополнить, рендереров не добавлять:

- граница наций — светлая линия по 4-соседям в шейдере, вода из палитры (индекс владельца 0 + `Terrain == Water` → цвет воды; для этого `Terrain` грузится второй `R8`-текстурой один раз за партию);
- свои фронты: пиксели, перешедшие за последние 10 с, подсвечиваются: свой новый — светлее, потерянный — темнее. Для этого игра сама (в `Game`, не в ядре) держит `byte[] flipAge` по разнице `Owner` между кадрами и грузит его третьей `R8`-текстурой `FrontFx`. Правило «одна текстура владельцев» — про то, что владельцы живут в одной текстуре без GameObject; эффекты в отдельной текстуре это правило не ломают;
- активный удар человека — пульс вдоль границы с целью (`_StrikeMask` — биты наций, по которым идёт удар человека, `_HumanId`);
- крепости и столицы — значки в шейдере по массиву uniform `_Markers[96]` (x, y, тип, владелец); кольцо радиуса рисуется только у выбранной крепости и в режиме постройки.

**HUD сверху:** золото, чистый доход/с (`+3,0`), батальоны и содержание (`12 · −3,0/с`), доля суши и порог (`14% / 40%`), таймер до конца (`38:12`). Пауза, ×1, ×2, ×4.

**Три кнопки снизу:** «Батальон 200», «Крепость 400», «Удар». Цена на кнопке всегда текущая.

- «Батальон» — одно нажатие, команда на следующий тик.
- «Крепость» — режим постройки. Тап по своей земле показывает кольцо и кнопку «Поставить за 400». Тап мимо или «Отмена» — выход из режима.
- «Удар» — режим удара. Тап по любому пикселю соседа подсвечивает весь фронт с ним и показывает «Удар по Синим: −1 батальон, 20 с». Второе нажатие подтверждает. Подтверждение нужно: на таче легко промахнуться, а батальон не вернуть.

**Неактивная кнопка серая, но нажимается и объясняет причину** (тап-подсказка, закрывается тапом мимо):

| Причина | Текст |
| --- | --- |
| `NotEnoughGold` | «Не хватает 120 золота, это ~40 с» |
| `ArmyCap` | «Армия на пределе: 60 батальонов» |
| `NotOwnPixel` | «Крепость — только на своей земле» |
| `TooCloseToFort` | «Слишком близко к своей крепости» |
| `FortLimit` | «Больше крепостей не построить» |
| `NoBattalions` | «Нет батальонов для удара» |
| `NoContact` | «С ними нет общей границы» |

**Тап по карте вне режимов:**

- по соседу — плашка фронта: «Мы: 4,8 бат. на 120 px · Они: 6,0 на 120 px → они давят 1,2 : 1», ниже активные причины (удар, их крепость рядом, их столица рядом) и `NetFlips10s` («за 10 с: −7 px»);
- по своей земле — доход, батальоны, крепости;
- по крепости — владелец и радиус.

Числа в плашке берутся из тех же формул 5.4, что и фронт: игрок видит ровно те причины, которые двигают границу.

**Уведомления** (тост сверху, 3 с, не блокирует): «Синие ударили по нам», «Пала наша крепость», «Пала столица Зелёных». Больше никаких.

**Конец партии:** экран «Победа» или «Поражение» с причиной («Вы взяли 40% суши», «Пала столица», «Жёлтые взяли 40% суши», «Время вышло, крупнейшие — Синие»), минута, своя доля, кнопки «Ещё партия» (новый сид), «Та же карта» (тот же сид) и «Сохранить реплей».

Человек — нация 1. Сид новой партии в игре — от времени запуска, в адаптере (`Game`), не в ядре.

## 11. Edge cases

- На пиксель претендуют несколько соседей — бросают по порядку N, E, S, W, первый успешный забирает, один и тот же сосед бросает один раз.
- Две нации забирают пиксели друг друга в одном тике — так и есть, решения из фазы A независимы.
- Диагональный контакт не фронт (только 4-соседство).
- Анклав внутри чужой земли — обычный пограничный пиксель, ничего особого.
- `warLen(a) = 0` (у нации только ничья граница) — `armyOnFront` не считается, деления на 0 нет.
- Удар по нации, с которой контакт пропал после команды, — удар идёт до конца, но без фронта ни на что не действует. Батальон не возвращается.
- Цель удара пала — запись `StrikeUntil` обнуляется в `StrikeSystem`.
- Пала нация, по которой у человека активен удар, — пульс гаснет, уведомление «Пала столица …».
- Пиксель крепости захвачен — крепость пала; следующая крепость дешевле, потому что цена идёт по `FortsAlive`.
- Две столицы пали в одном тике — гибель по возрастанию id, `EndSystem` после этого.
- Человек и ИИ одновременно дошли до порога или человек пал в тот же тик, когда кто-то взял порог, — порядок проверок 5.7 решает (сначала поражение человека).
- Все ИИ пали, человек жив — `Conquest` человека.
- Золото ушло в минус от содержания — дезертирство по одному батальону в секунду, золото 0.
- Команда человека на паузе — ставится на `Tick + 1`, применяется при следующем тике.
- Команда от мёртвой нации или с `Nation = 0` — `NationInvalid`.
- Игровая команда в мире без правил — `RulesDisabled`.
- Генератор не набрал сушу или честные старты за все попытки — берёт лучшую попытку, ставит флаг, партия идёт.
- Реплей формата 1 — понятная ошибка, код выхода 2.
- Нечётные размеры карты, `nations` от 2 до 12 — работают. Маска `FortCover` — `ushort`, до 16 наций.

## 12. Acceptance criteria

Каждый пункт проверяется тестом или командой.

1. Тесты Фундамента зелёные без изменений их ожиданий (старый конструктор `Simulation`).
2. `CoreHasNoForbiddenApis` проходит на новом коде ядра.
3. `Pcg32.Hash` совпадает с 3 векторами, посчитанными эталонной реализацией из 4.3.
4. Генерация: на сидах 1–100 суша 45–49% карты, ровно один компонент суши, 8 столиц на суше не ближе 6 px к воде, флаги `mapRetryFail` и `unfairStart` в ≤ 5% сидов. Генерация ≤ 200 мс.
5. `FrontExampleTests` воспроизводит таблицу из раздела 6: `pow`, `ratio_bp` и `chance_bp` для всех пяти строк.
6. Тест на одном тике: искусственная пара наций, фиксированные `salt` и пиксели, ожидаемые решения фазы A посчитаны вручную по хешу из 4.3.
7. `FrontJob` с 1 потоком и со всеми потоками даёт одинаковый хеш на сидах 1–10 через 3 000 тиков.
8. `DerivedStateMatches`: на сидах 1–10 каждые 600 тиков `FortCover`, `FrontLen`, `Frontier` и `Pixels` совпадают с пересчётом с нуля.
9. `HashJob` и `HashManaged` совпадают на 10 случайных мирах с правилами.
10. `-determinism 42` с правилами проходит; сиды 1 и 2 дают разные финальные хеши.
11. Реплей из игры (человек отдал ≥ 20 команд всех трёх типов) проходит `-replay` бит в бит. В нём нет ни одной команды ИИ. Подмена одной команды человека ловится на первой расходящейся контрольной точке.
12. Валидация: на каждую причину из `RejectReason` 4–13 есть тест, где команда отклоняется, а мир не меняется.
13. Экономика: тест секунды из раздела 6 (`+300` в сотых), тест дезертирства.
14. Конец: тесты на все четыре ветки 5.7 и на порядок проверок при одновременных событиях.
15. Гибель нации: её земля становится ничьей, крепости сняты, пиксели, взятые в том же тике другими, остались у них.
16. `-seeds 1-100` без флагов: код 0, отчёт со всеми строками раздела 8. Сами цели ворот 1 на этом шаге не обязаны выполняться: это вход для балансной итерации. Отчёт честно пишет «провал», цифры не подгоняются.
17. `-profile 1=no_forts` и `-profile 1=no_strikes` отрабатывают и дают строку сравнения в `report.md`.
18. `-analyze` на реплее из п. 11 печатает решения за первые 10 минут и `fortOverArmy`.
19. В игре: три кнопки и HUD, все ≥ 44×44; каждая причина отказа из таблицы раздела 10 показывается по тапу; плашка фронта показывает числа, совпадающие с `ArmyOnFront` и `pow` из ядра; партия доходит до экрана конца.
20. 60 fps на ×4 в 1080p с 8 нациями (Unity Profiler, числа в PR); средний тик и p99 в отчёте раннера.
