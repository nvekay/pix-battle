## 1. Цель и решение игрока

Армия больше не размазывается по границе сама. Она собрана в соединения, и игрок решает, где каждое стоит и что делает. Армии на все фронты не хватает: наступать можно там, где сосредоточился, платя тонким фронтом в другом месте. Рельеф делает состав решением: броня рвёт равнину и вязнет в горах.

| Решение | Команда | Цена |
| --- | --- | --- |
| Куда поставить соединение | `AssignFormation` | работает только там, где стоит; переброска 30 с без силы; неприкрытый фронт держит гарнизон |
| Наступление или оборона | `SetOrder` | наступление берёт землю, но теряет численность и держит хуже (×0,7); оборона землю не берёт |
| Пехота или броня | `RecruitUnit` | пехота 150, держит; броня 400, атака на равнине ×1,3, в горах ×0,4 |
| Новый штаб или батальон в старый | `RecruitUnit` с `A = −1` | штаб 300 и содержание, зато ещё одна независимая единица |

Если на плейтесте никто ни разу не набрал броню или не держал фронт в обороне ради наступления на другом, крутим числа раздела 9, а не добавляем фичи.

1. Всё из CLAUDE.md и из раздела 3 spec-01 (хеш на пиксель, две фазы, ИИ через ту же очередь, ИИ-команды не в реплее, числа только в данных).

## 4. Данные

### 4.1. Рельеф

`enum Terrain : byte { Water = 0, Land = 1, Hills = 2, Mountains = 3 }`. `Land` теперь значит «равнина», значения дописаны. **Все проверки «это суша» переводятся на `terrain != Water`** (сейчас их 12, в ядре, тестах и ИИ, через `== Terrain.Land`; `World.IsLand` тоже). Это первый коммит переделки, после него тесты Фундамента и spec-01 должны остаться зелёными без смены ожиданий.

Индекс рельефа в таблицах: `tr = terrain − 1` (0 равнина, 1 холмы, 2 горы).

| Поле | Тип | Пехота (0) | Броня (1) |

| Поле | Тип | В хеше |
| --- | --- | --- |
| `FormationsArr` | `NativeArray<Formation>` `N × maxFormationsPerNation` | да |

`RngStream` не меняется: случайности в новых системах нет, кроме шума ИИ (`Ai`).

### 4.4. Команды

```csharp
public enum CommandType : byte {
    Noop = 0, DebugSetOwner = 1,
    Recruit = 2, BuildFort = 3, Strike = 4,   // устарели: Obsolete
    RecruitUnit = 5,      // A = номер соединения k (−1 — новое со штабом), B = тип батальона
    AssignFormation = 6,  // A = k, B = id противника (0 — в тыл)
    SetOrder = 7,         // A = k, B = 0 оборона / 1 наступление
}
// RejectReason дописать:
//   Obsolete = 15, FormationInvalid = 16, FormationFull = 17, FormationLimit = 18,
//   UnitTypeInvalid = 19, AlreadyThere = 20, OrderInvalid = 21
```

Валидация в момент применения, порядок `(Nation, Seq)` как было:

- **RecruitUnit.** Нация жива; `0 ≤ B < units.Length` (`UnitTypeInvalid`). Если `A = −1`: `Formations < maxFormationsPerNation` (`FormationLimit`), `Gold ≥ hqCost_c + cost_c`; новое соединение занимает первый свободный слот, `Front = 0`, `Order = 0`, `ArriveTick = 0`. Иначе: соединение `A` живое и своё (`FormationInvalid`), в нём `< maxBattalions` живых (`FormationFull`), `Gold ≥ cost_c`. Общий `Battalions < battalionCap` (`ArmyCap`, страховка). Применение: списать, батальон в первый свободный слот соединения, `Strength_bp = 10 000`, счётчики. Батальон в соединении, которое стоит на фронте, начинает работать со следующего тика (переброски нет: штаб уже там).
- **AssignFormation.** Соединение живое и своё. `B = 0` — в тыл: `Front = 0`, `ArriveTick = 0` сразу. `B ≠ 0`: `1 ≤ B ≤ N`, `B ≠ Nation`, противник жив (`TargetInvalid`), `FrontLen[Nation, B] > 0` (`NoContact`), `B ≠ Front` или соединение ещё в пути на другой фронт (`AlreadyThere`). Применение: `Front = B`, `ArriveTick = Tick + transferTicks`. Повторное назначение в пути перезапускает таймер.
- **SetOrder.** Соединение живое и своё; `B ∈ {0, 1}` (`OrderInvalid`). Применяется сразу, в том числе в пути и в тылу (в тылу приказ хранится, но ничего не делает).
- **Recruit / BuildFort / Strike** в мире с правилами → `Obsolete`. В мире без правил — `RulesDisabled`, как было.

## 5. Правила и формулы

### 5.1. Сила сторон на фронте (`FormationSystem.FillPow`, до фазы A, каждый тик)

Для каждой живой нации `a`, каждого `d` с `FrontLen[a, d] > 0`, каждого рельефа `tr`:

```
// очки ×100, по батальонам соединений a с Front == d и ArriveTick ≤ Tick
att100(a,d,tr) = Σ (наступление)   attack[type] × 100 × attackTerrain_bp[type][tr] / 10000 × Strength_bp / 10000
def100(a,d,tr) = Σ (любой приказ)  defense[type] × 100 × defenseTerrain_bp[type][tr] / 10000 × Strength_bp / 10000 × (Order == 1 ? attackingDefense_bp : 10000) / 10000

attPow(a,d,tr) = att100 / FrontLen[a,d]
defPow(a,d,tr) = (def100 / FrontLen[a,d] + garrisonPerEdge) × terrainDefense_bp[tr] / 10000
```

Каждое деление — к нулю, в том порядке, как записано; промежуточные в `long`. Гарнизон теперь только обороняет: нация без наступающих соединений на фронте не берёт там ни пикселя.

### 5.2. Шанс захвата (`FrontSystem.FillTables`)

Таблица `Chance` расширяется измерением рельефа: индекс `((a × stride + d) × 2 + capFlag) × 3 + tr` (флаг крепости уходит, остаётся флаг столицы):

```
att     = attPow(a,d,tr)
defMult = capFlag ? capitalMult_bp : 10000;  defMult = min(defMult, defenseMultCap_bp)
def     = defPow(d,a,tr) × defMult / 10000
chance  = FrontMath.Chance(att, def, warChance_bp, stallRatio_bp, maxChance_bp)   // как было
```

`att = 0` → `chance = 0`. Ничья земля: `expandChance_bp` от любого соседа-нации, как было, рельеф не влияет. В `FrontJob` поменять только чтение индекса (`tr` по рельефу пикселя-цели `t`) и проверки суши (4.1). Множитель окружения — как было.

### 5.3. Потери и пополнение (`FormationSystem`, раз в секунду, после `EconomySystem`)

Взвешенные силы пары за секунду (по рельефу фронта `d`):

```
A(a,d) = Σ_tr attPow(a,d,tr) × FrontTerrainLen[a,d,tr]
D(d,a) = Σ_tr defPow(d,a,tr) × FrontTerrainLen[a,d,tr]
```

Для каждого батальона соединения `a` на фронте `d` (на месте, не в пути):

```
если Order == 1 и A(a,d) > 0:   loss = attackLoss_bp × clamp(D(d,a) × 10000 / A(a,d), lossRatioMin_bp, lossRatioMax_bp) / 10000
если A(d,a) > 0 (на нас наступают): loss += defendLoss_bp × clamp(A(d,a) × 10000 / max(D(a,d),1), lossRatioMin_bp, lossRatioMax_bp) / 10000
Strength_bp −= loss
```

Потом пополнение, по нациям по id, по слотам соединений и батальонов:

```
rate  = (Front == 0 || ArriveTick > Tick) ? reinforceRear_bp : reinforceFront_bp
add   = min(rate, 10000 − Strength_bp)
price = cost_c[type] × add / 10000 × reinforceCostMult_bp / 10000
если Gold ≥ price: Gold −= price, Strength_bp += add       // иначе этот батальон в эту секунду не пополняется
```

Батальон с `Strength_bp ≤ 0` гибнет: `Alive = 0`, `Battalions −= 1`, `BattalionsLost += 1`. Соединение без батальонов живёт (штаб платит содержание) и ждёт набора: роспуска в этапе 1 нет.

### 5.4. Экономика (дельта к spec-01 §5.6)

```
upkeep_c = Σ живые батальоны upkeep_c[type] + Formations × hqUpkeep_c
```

Дезертирство при `Gold < 0`: гибнет один батальон — с наименьшим `Strength_bp`, при равенстве с наибольшим слотом; `Gold = 0`. Порядок секунды: доход и содержание → дезертирство → потери → пополнение.

### 5.5. Закрытие фронта (`FormationSystem`, каждый тик после `FrontSystem`)

Соединение с `Front = d`, у которого `FrontLen[owner, d] = 0` или `d` мёртв, уходит в тыл: `Front = 0`, `ArriveTick = 0`. Для человека — тост (раздел 10).

### 5.6. Порядок тика

1. Команды тика.
2. `FormationSystem.FillPow` (5.1).
3. `FrontSystem`: соль, `FillTables` (5.2), фаза A, фаза B, `FrontLen` + `FrontTerrainLen`, гибель столиц.
4. `FormationSystem.CloseFronts` (5.5).
5. `EconomySystem` раз в секунду (5.4), потом `FormationSystem` потери и пополнение (5.3).
6. `AiSystem` (5.8).
7. `EndSystem` — как было.
8. `Tick += 1`, контрольная точка.

Гибель нации (spec-01 §5.5 п. 3) дополнительно: все её соединения и батальоны `Alive = 0`, `Battalions = 0`, `Formations = 0`.

### 5.7. Рельеф в генерации (`MapGen`, шаг 3½, без новых вызовов `Next()`)

После порога суши и выбора континента: гистограмма высот только по пикселям суши, тем же способом, что для порога суши. Верхние `mountainsShare_bp` суши — `Mountains`, следующие `hillsShare_bp` — `Hills`, остальное — `Land`. Столица не ставится в горах (условие кандидата дописать). Генерация не делает новых вызовов `MapGen`, поэтому карты на тех же сидах те же, меняется только рельеф суши (это проверяется тестом).

Стартовое: каждой нации одно соединение (слот 0, в тылу, оборона) с `startInfantry` пехоты на 100%; `startBattalions` убрать.

### 5.8. ИИ (`AiSystem`, одна команда за раз, думает раз в `thinkIntervalTicks` со сдвигом, как было)

Оценки на момент думанья (`self` = нация ИИ, фронты — `d` с `FrontLen > 0`):

```
threat(d)   = A(d,self) × 10000 / max(D(self,d),1)                  // давят ли нас
plainShare(d) = FrontTerrainLen[self,d,0] × 10000 / FrontLen[self,d]
opp(d)      = потенциальная атака всех своих соединений на d (как если бы все наступали там) × 10000 / max(D(d,self),1)
              + (доля d от суши ≥ leaderShare_bp ? leaderBonus_bp : 0) + Ai.NextInt(noise_bp + 1)
target      = d с max opp(d); при равенстве меньший id
avgStr(f)   = средняя Strength_bp батальонов соединения
```

Правила сверху вниз, первое сработавшее отдаёт команду:

1. **Отвести обескровленное.** Соединение в наступлении с `avgStr < retreatStrength_bp` → `SetOrder 0`; если оно уже в обороне и `avgStr < rearStrength_bp`, а на его фронте `threat < threatRatio_bp` → `AssignFormation 0` (в тыл, пополняться).
2. **Закрыть прорыв.** Фронт с `threat ≥ threatRatio_bp` и без своих соединений на месте или в пути → туда соединение из тыла с `avgStr ≥ deployStrength_bp`; если в тылу никого, — с фронта с наименьшим `threat`, кроме `target`. Приказ «оборона».
3. **Ударный кулак.** Соединения в тылу с `avgStr ≥ deployStrength_bp` → `AssignFormation target`.
4. **Наступать обязательно.** Если ни одно своё соединение не наступает, а на `target` есть соединение на месте с `avgStr ≥ attackStrength_bp` и `opp(target) ≥ attackMinRatio_bp` → `SetOrder 1` ему. Если `opp` ниже порога, ждать подкрепления (правило 5).
5. **Набор.** Если золото ≥ цены с запасом `recruitReserve_c`: тип — броня, если `plainShare(target) ≥ armorPlainShare_bp` и доля брони в армии `< armorMaxShare_bp`, иначе пехота. Куда — соединение на `target` с `< maxBattalions`; иначе любое неполное; иначе новое (`A = −1`), если хватает на штаб.

Профили `ai.json` (полные, без наследования): `base`; `spread` — правила 2–4 заменены на «каждое соединение из тыла — на фронт с наименьшей суммой `def100` на ребро, приказ наступление» (так делал прототип: ровный слой); `no_armor` — `armorPlainShare_bp = 1 000 000`. `spread` и `no_armor` — абляции для отчёта.

## 6. Пример расчёта на одном тике

Красные (1) против Синих (2), `FrontLen[1,2] = 120`, по рельефу синих пикселей 72 / 36 / 12 (равнина / холмы / горы). `garrisonPerEdge = 40`, `terrainDefense_bp = [10 000, 12 500, 15 000]`, `warChance_bp = 180`, `stallRatio_bp = 8 000`, `maxChance_bp = 800`. Все на 100%, никто в пути, столицы далеко.

Красные: соединение 1 — 8 пехоты + 3 брони, наступление. Синие: одно соединение 10 пехоты, оборона.

| | Равнина | Холмы | Горы |
| --- | --- | --- | --- |
| `att100` Красных: 8 × 1 000 + 3 × 2 600 × mult | 8 000 + 10 140 = 18 140 | 8 000 + 6 240 = 14 240 | 7 200 + 3 120 = 10 320 |
| `attPow(1,2)` = / 120 | 151 | 118 | 86 |
| `def100` Синих: 10 × 1 400 | 14 000 | 14 000 | 14 000 |
| `defPow(2,1)` = (14 000 / 120 + 40) × рельеф | 156 | 195 | 234 |
| `ratio_bp` | 9 679 | 6 051 | 3 675 |
| `chance_bp` = 180 × (ratio − 8 000) / 10 000 | **30** | **0** | **0** |

Одно соединение против равного по деньгам защитника едва ползёт по равнине и стоит в холмах. Теперь Красные приводят второе соединение (8 пехоты, наступление), а фронт с Зелёными оставляют одному гарнизону:

| | Равнина | Холмы | Горы |
| --- | --- | --- | --- |
| `att100` | 26 140 | 22 240 | 17 520 |
| `attPow` | 217 | 185 | 146 |
| `ratio_bp` | 13 910 | 9 487 | 6 239 |
| `chance_bp` | **106** | **26** | **0** |

Это и есть картинка, ради которой механика: граница рвётся по равнине, ползёт по холмам, в горах стоит. Синие у себя ничего не берут: у них нет наступающих соединений.

Потери Красных в конце секунды (второй вариант): `A(1,2) = 217 × 72 + 185 × 36 + 146 × 12 = 24 036`, `D(2,1) = 156 × 72 + 195 × 36 + 234 × 12 = 21 060`, отношение 8 761 → `loss = 50 × 8 761 / 10 000 = 43` bp/с у каждого наступающего батальона. Пополнение на фронте 30 bp/с: чистая убыль 0,13%/с, через ~4 минуты соединениям пора в тыл. Цена пополнения за эту секунду: 16 пехоты × (15 000 × 30 / 10 000 × 2 000 / 10 000 = 9) + 3 брони × 24 = 216 в сотых, 2,2 золота/с. Синие теряют `20 × clamp(11 413) / 10 000 = 22` bp/с.

Решение по пикселю: `roll = hash(salt, t, k)` как в spec-01 §4.3. Агент собирает конкретный пример с реальной солью в `FrontExampleTests` (acceptance 5).

## 7. Тик и цена по CPU

- `FillPow`: до 128 соединений × 12 батальонов × 3 рельефа — около 5 тыс. умножений на тик, managed-код в порядке слотов допустим; если тик вырос > 0,02 мс — в Burst `IJob`.
- `FillTables`: `(N+1)² × 2 × 3` записей вместо `× 4` — то же порядка.
- `FrontTerrainLen` — в том же проходе, что `FrontLen`, без нового прохода.
- Потери и пополнение — раз в секунду, ~1,5 тыс. батальонов.
- **Бюджет:** средний тик ≤ 0,25 мс (CLAUDE.md), p99 ≤ 2 мс. Сейчас 0,06 мс; рост больше чем до 0,1 мс — объяснить в PR. Цифры не подгонять.
- 60 fps на ×4 в 1080p с 8 нациями.

## 8. Входы и выходы к другим системам

**Отдаёт этапу 2:** `Formation.Front = 0` как точку, куда перемирие сбрасывает соединения; `units` в данных для артиллерии; `BattalionsLost` и численность — основа для рабочих; `FrontTerrainLen` — для зданий-укреплений, если они понадобятся.

**Headless-раннер.** `MatchResult` дополнить по нациям: `RecruitedInf`, `RecruitedArmor`, `BattalionsLost`, пик `Formations`, доля секунд, когда у нации ≥ 1 соединение наступает (`attackTime_bp`), доля секунд «фокуса» — одновременно наступление на одном фронте и ни одного наступающего на другом существующем фронте (`focusTime_bp`). Убрать `Strikes`, `FortsBuilt`.

`report.md`: строки ворот 1 из spec-01 §8 остаются (кроме удалённых счётчиков). Цели из плана редакции 4 для ворот 1: «100% партий заканчиваются победой или поражением» и «никто не захватил всё за 10 минут». Строку «по таймеру ≤ 10%» оставить, но пометить «справочно до ворот 2»: по букве плана партия по таймеру тоже кончается победой, и без этой строки стагнация прототипа прошла бы ворота. Новые строки: средние по нациям `attackTime_bp`, `focusTime_bp`, доля брони в наборе, потери; при `-profile` — «победы профиля X у нации N» против прогона без абляции.

**`-analyze <replay>`** по партии человека: исход и минута; команды по типам; решений за 10 минут (цель ≥ 10 по плану); **фокус-эпизоды** — отрезки ≥ 30 с, когда у человека соединение наступало на одном фронте, а другой существующий фронт стоял в обороне или пустой (цель ≥ 1); **состав под рельеф** — наборы брони при `plainShare` фронта этого соединения ≥ 60% и пехоты при ≤ 40% (цель ≥ 1). Метрика ворот 1 выполнена, если ≥ 1 по любой из двух.

## 11. Edge cases

- Соединение в пути, а фронт закрылся — уходит в тыл (5.5), таймер обнуляется.
- Назначение на фронт, где соединение уже стоит на месте, — `AlreadyThere`, мир не меняется.
- Фронт делится на два куска (анклав, разрез) — это всё ещё один фронт пары, сила делится на общую длину. Карман отдельным фронтом не становится (решение брифа).
- Соединение без батальонов на фронте — сила 0, но считается «своим соединением на месте» для значка и для правила 2 ИИ. ИИ такое соединение отводит в тыл (правило 1, `avgStr` пустого = 0).
- Две нации наступают друг на друга на одном фронте — обе бросают по своим пикселям-целям, обе несут потери от атаки и от обороны.
- Наступление на фронте, где противника нет (только гарнизон), — потери считаются от `D` гарнизона; при `A = 0` потерь от атаки нет.
- Денег на пополнение нет — численность не растёт, батальоны не гибнут от этого сами.
- `FrontLen = 0` в момент `FillPow` — сила не считается, деления на 0 нет.
- Пиксель-цель на горе, рядом столица — множители обороны: рельеф в `defPow`, столица в `defMult`, кап `defenseMultCap_bp` применяется только к столице, как было.
- Нация пала — её соединения сняты в тот же тик, у противников они уходят в тыл на следующем тике (5.5).
- Реплей формата 2 — код 2.
- `units` пустой или больше 8 типов — ошибка `Validate`.

## 12. Acceptance criteria

1. Тесты Фундамента зелёные без смены ожиданий. `CoreHasNoForbiddenApis` проходит.
2. После коммита «суша = не вода» (4.1) все тесты spec-01 зелёные, финальный хеш `-determinism 42` совпадает с `main`.
3. Генерация: на сидах 1–100 карты суши совпадают с `main` по `Owner`/суше бит в бит; доля гор 9–11% и холмов 24–26% суши; ни одна столица не в горах.
4. `FillPow` и `FillTables` воспроизводят обе таблицы раздела 6 (тест `FormationPowTests`), включая округления.
5. `FrontExampleTests`: искусственная пара с рельефом, фиксированная соль, ожидаемые решения фазы A посчитаны вручную.
6. Потери и пополнение: тест секунды из раздела 6 (`43`, `22`, `216`), гибель батальона на 0, дезертирство по правилу 5.4.
7. Валидация: на каждую причину `Obsolete`…`OrderInvalid`, `NotEnoughGold`, `ArmyCap`, `NoContact`, `TargetInvalid` — тест, где команда отклоняется, а мир не меняется.
8. Перемещение: соединение в пути не даёт силы до `ArriveTick`, на `ArriveTick` даёт; закрытие фронта отправляет в тыл.
9. `FrontJob` с 1 потоком и со всеми потоками — одинаковый хеш на сидах 1–10 через 3 000 тиков.
10. `DerivedStateMatches` на сидах 1–10 каждые 600 тиков, включая `FrontTerrainLen`, `Battalions`, `Formations`.
11. `HashJob` и `HashManaged` совпадают на 10 случайных мирах с соединениями.
12. `-determinism 42` проходит; реплей из игры (≥ 20 команд всех трёх новых типов) проходит `-replay` бит в бит; подмена одной команды ловится; реплей формата 2 — код 2.
13. `-seeds 1-100`: код 0, отчёт со всеми строками раздела 8; средний тик ≤ 0,25 мс. Сами цели ворот на этом шаге выполняться не обязаны, отчёт пишет «провал» честно.
14. `-profile 1=spread` и `-profile 1=no_armor` отрабатывают и дают строки сравнения. Ожидание (не блокирует PR, но идёт в описание): `base` побеждает чаще `spread`; если нет — сосредоточение ничего не стоит, это вход для итерации.
15. `-analyze` на реплее из п. 12 печатает фокус-эпизоды и наборы под рельеф.
16. В игре: панели «Фронты» и «Соединения», назначение кликами, приказы, набор обоих типов, новый штаб; каждая причина из таблицы раздела 10 видна по клику; числа плашки совпадают с `AttPow`/`DefPow` ядра; значки штабов на фронтах; рельеф виден на карте; партия доходит до экрана конца.
17. 60 fps на ×4 в 1080p с 8 нациями, цифры в PR.
